# Rozjede to? – project context

A Czech website: the visitor enters their CPU, GPU and RAM and sees, for each game, whether their PC meets the game's minimum / recommended requirements. The owner is a programming beginner: explain simply, in Czech, and when changing service settings (GitHub, Supabase, Vercel, RAWG) say exactly where to click. The site's UI is **Czech** (its selling point is a Czech-language tool). This is a separate project from the owner's game library (`Desktop\my-games-web`).

## Architecture
- Static site, no build step: `index.html` + `style.css` + `app.js` (games, verdicts) + `builds.js` (saved builds, sign-in). Hosting: Vercel, deployed from GitHub.
- **Data flow (option "B", chosen by the owner):** Supabase is the source of truth for games and parts; the website never reads them from Supabase – it loads the generated files `data/parts.js` and `data/games.js` (fast, no Supabase egress limits).
  - `.github/workflows/update-data.yml` – weekly (Mon 04:00 UTC) + by hand: `MODE=full node tools/update-data.js` → parts from Supabase (an empty `parts` table is first filled from `data/parts.js`) → RAWG crawl → upsert into `games` (rows with `manual = true` are skipped) → export both data files → commit. The weekly write also keeps the free Supabase project from pausing.
  - `.github/workflows/publish-db.yml` – "Publikovat změny z databáze", by hand: `MODE=export` → just Supabase → data files (for the owner's edits).
  - Secrets: `RAWG_API_KEY`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (secret/service-role key – **never** in the website or any file). Without the Supabase secrets `update-data.js` falls back to RAWG → `data/games.js` directly.
  - Safety: never publishes or writes fewer than 50 games.
- **Supabase tables** (`supabase.sql`, safe to re-run): `builds` (visitors' saved builds, RLS own rows), `parts` (`kind` cpu/gpu, `name`, `score`, `hidden`, `aliases text[]`; RLS on, no policies), `games` (RAWG id, name, `min`/`rec` jsonb `{cpu:[names]|null, gpu:[names]|null, ram}`, `req_text`, `no_req`, `pop`, `released`, `upcoming`, `manual`…; RLS on, no policies). Trigger `games_mark_manual`: any insert/update not made as `service_role` sets `manual = true` (so dashboard edits survive the weekly update); unticking `manual` yourself is allowed and lets RAWG update the game again. At export, `upcoming` is recomputed from `released` vs. today.
- `tools/db.js` – tiny PostgREST client (fetch, paging by 1000, upsert in batches of 500). `tools/crawl.js` – RAWG crawler (shared by the updater and `tools/builder.html`). `tools/parse.js` – requirement text → part names. `tools/test.html` – parser test page. `tools/builder.html` – manual fallback (RAWG → games.js in the browser; key typed by hand, never stored). `tools/dev-server.ps1` – local preview server (`http://localhost:5180/index.html`) with a local-only `POST /__save/data/*.js` helper because the app's browser pane can't download files.
- **Parts** (~420 CPUs, ~280 GPUs selectable + hidden generic entries like "obecný dvoujádrový procesor 2,4 GHz" or "obecný Core i7"): `{ name, score, hidden }`, scores are **our own rough estimates** on one scale (GTX 1060 6GB = 100, Core i5-8400 = 100). `PART_ALIASES` maps short names ("GTX 1060") to one model. Typed names are matched ignoring case, spaces, dashes and brand words; integrated GPUs also match without "(integrovaná)". Game requirements refer to parts by **name** – renaming a part in Supabase breaks games that use the old name (add the old name to `aliases` instead).
- **RAWG crawl**: PC games (`platforms=4`, `ordering=-added`); the list endpoint has no requirements, so 1 detail request per game. Budget chosen by the owner: **3 500 popular + 100 most-anticipated games releasing within the next month** ≈ 3 700 requests per weekly run ≈ 18 500 in a month with five Mondays (free tier 20 000) – so a manual full run costs real budget; use "Publikovat změny z databáze" for manual changes. Counts are `crawl.js` options `popular` / `upcoming` / `months` (env `POPULAR`, `UPCOMING`, `MONTHS` in the workflow). First run (25 Nov 2026): 2 030 seen, 1 788 with requirements, 1 123 fully recognised (~63 %). RAWG requirements are sometimes outdated (Cyberpunk 2077 shows 2020 specs). The upcoming query returned only ~30 games → the release calendar is thin; Steam "coming soon" + appdetails would be a better source (not done). Every game is kept: picture fallback (main → second image → screenshot), `pop` = popularity rank (default sort), `reqText` = original text where something wasn't recognised, `noReq` when RAWG has no requirements.
- **Verdict**: per component great (meets recommended) / ok (minimum only) / no; game = worst known component. CPU/GPU 5 % tolerance, RAM exact. Only CPU or only GPU recognised → "Asi rozjedeš / Asi na nízké detaily" (dashed badge); none → grey "Požadavky nerozpoznány" + original text in the detail; no requirements → "Požadavky neznámé". Threshold = weakest listed alternative. `app.js` warns in the console about unknown part names – keep it clean.
- **Site UI**: tabs "Hry" (paged 48 at a time; sort Nejpopulárnější/Podle názvu/Nejnovější/Nejnáročnější/Nejméně náročné) and "Kalendář vydání" (upcoming by month). RAWG images via `/media/resize/640/-/`; no picture → coloured placeholder with the first letter. RAWG attribution link in the footer is required by their terms.
- **Saved builds** (`builds.js`, `config.js` with Supabase URL + public key): named builds; not signed in → `localStorage` (`rozjede-builds`); signed in (magic link) → table `builds`, browser builds move into the account on sign-in. The sign-in button is hidden until `config.js` is filled in. Supabase's built-in email sender allows only a few emails per hour – for real traffic set up custom SMTP or add Discord/Google sign-in.

## Don't
- Don't scrape PassMark, UserBenchmark, TechPowerUp or similar benchmark sites – no public API and their terms likely forbid it. License data (PassMark sells it) or use openly licensed data (check the licence first).
- Don't present the result as a guarantee; the footer says it's an estimate.
- Don't put any key except Supabase's *public* key into files.
